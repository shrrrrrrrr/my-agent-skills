# 软件工程标准流程

以可验收、可验证、可回滚为核心。根据任务规模裁剪流程，不为小改动制造形式主义。

1. 明确目标、非目标、约束和验收标准。
2. 检查现有代码、项目说明、测试和未提交改动。
3. 识别风险与不可逆决策，选择最小可行方案。
4. 将工作拆成可单独验证的纵向任务。
5. 先建立失败证据或测试，再实施最小改动。
6. 在每个阶段运行相关检查；失败时先定位根因。
7. 审查正确性、安全性、性能、兼容性和可维护性。
8. 完成最终构建或测试，记录变更、风险、回滚和后续工作。

未经授权不扩展产品范围，不覆盖用户已有改动，不把“看起来合理”当作验证结果。
